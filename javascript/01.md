# JavaScript – Notas iniciales

Este archivo recoge algunos conceptos básicos de JavaScript que he ido aprendiendo o repasando, relacionados con el comportamiento del lenguaje y sus particularidades.

---

## Valores truthy y falsy

En JavaScript, cualquier valor puede evaluarse como verdadero o falso en un contexto booleano, como una condición `if`.

Los valores considerados falsy son:

- false
- 0
- -0
- 0n
- ""
- null
- undefined
- NaN

Cualquier otro valor se considera truthy, incluso si puede parecer “vacío”, como un array vacío o un objeto vacío.

Esto es importante tenerlo en cuenta para evitar condiciones incorrectas o bugs difíciles de detectar.

---

## Diferencia entre == y === en JavaScript

JavaScript dispone de dos operadores de comparación de igualdad: `==` y `===`, cuyo comportamiento es diferente.

El operador `==` realiza una comparación con coerción de tipos, lo que significa que intenta convertir los valores antes de compararlos.

El operador `===` compara tanto el valor como el tipo, sin realizar conversiones implícitas.

Por este motivo, el uso de `===` es generalmente preferido, ya que evita comportamientos inesperados y hace el código más predecible.

---

## Nullish coalescing (??) en JavaScript

El operador nullish coalescing `??` permite proporcionar un valor por defecto cuando la expresión de la izquierda es `null` o `undefined`, evitando algunos comportamientos inesperados del operador `||`.

La diferencia clave es que `||` considera falsy valores como 0, "" o false, mientras que `??` solo actúa ante null o undefined.

Ejemplo:

    const a = 0;
    const conOr = a || 10;      // devuelve 10
    const conNullish = a ?? 10; // devuelve 0

Este operador es útil cuando 0 o "" son valores válidos y no quieres reemplazarlos por un valor por defecto.

# Event loop y microtasks en JavaScript

JavaScript ejecuta el código en un hilo principal, y el event loop gestiona cuándo se ejecutan tareas pendientes.

Hay una diferencia importante entre:

- macrotasks (por ejemplo, setTimeout)
- microtasks (por ejemplo, Promises)

Las microtasks suelen ejecutarse antes de pasar a la siguiente macrotask, por lo que una Promise resuelta puede “adelantarse” a un setTimeout con 0ms.

Entender esta diferencia ayuda a depurar comportamientos asíncronos y a evitar suposiciones incorrectas sobre el orden de ejecución.

# JavaScript – Nullish coalescing (??)

El operador nullish coalescing ?? permite usar un valor por defecto cuando la parte izquierda es null o undefined, evitando algunos casos típicos donde || da resultados inesperados.

---

# Diferencia entre || y ??

El operador || usa el concepto de “falsy”, por lo que trata como falso a 0, "" o false, incluso si esos valores son válidos para tu caso.

Con ?? solo se reemplaza cuando el valor es null o undefined.

Ejemplo:

    const a = 0;
    const conOr = a || 10;
    const conNullish = a ?? 10;

En este ejemplo, conOr termina siendo 10, mientras que conNullish termina siendo 0.

# JavaScript – Event loop y microtasks

JavaScript ejecuta el código en un hilo principal y utiliza un event loop para gestionar tareas pendientes. No todas las tareas se comportan igual: hay diferencias entre macrotasks y microtasks.

---

# Microtasks (Promises) vs Macrotasks (setTimeout)

Las Promises suelen encolarse como microtasks, y setTimeout típicamente encola una macrotask. En muchos casos, las microtasks se ejecutan antes de pasar a la siguiente macrotask, lo que puede hacer que una Promise resuelta “se adelante” a un setTimeout con 0ms.

Entender esto ayuda a depurar comportamientos asíncronos y a no asumir un orden de ejecución incorrecto.

# JavaScript – Closures (cierres)

Un closure ocurre cuando una función recuerda el contexto en el que fue creada, incluso si se ejecuta más tarde fuera de ese ámbito. Esto es una base importante para entender callbacks, handlers, factories y patrones comunes en JavaScript.

-Caso típico

Una función interna puede usar variables de la función externa:

    function createCounter() {
      let count = 0;
      return function () {
        count += 1;
        return count;
      };
    }

    const counter = createCounter();
    counter(); // 1
    counter(); // 2

Aquí la función devuelta “recuerda” la variable count.



## Por qué importa

Entender closures ayuda a evitar errores típicos (por ejemplo, variables compartidas sin querer) y a escribir código más expresivo para estados privados, configuración y funciones generadoras.

# JavaScript – map vs forEach

map y forEach recorren arrays, pero tienen propósitos distintos y conviene elegir bien.

---

## map

map crea un nuevo array transformando cada elemento.

Se usa cuando quieres “convertir” un array en otro:

    const nums = [1, 2, 3];
    const doubled = nums.map(n => n * 2);

---

## forEach

forEach recorre para ejecutar efectos secundarios (side effects), por ejemplo actualizar el DOM, registrar logs o acumular en una variable externa.

No devuelve un nuevo array útil (devuelve undefined), así que no es ideal para transformaciones.

---

## Regla rápida

- Si quieres un nuevo array: map
- Si quieres ejecutar acciones: forEach

---

# JavaScript – Destructuring (objetos y arrays)

El destructuring permite extraer valores de objetos y arrays de forma concisa, lo que puede mejorar la legibilidad cuando se usa con moderación.

---

## Destructuring en objetos

Permite extraer propiedades por nombre:

    const user = { name: "Jorge", age: 30 };
    const { name, age } = user;

También se puede renombrar:

    const { name: userName } = user;

---

## Destructuring en arrays

Extrae por posición:

    const coords = [10, 20];
    const [x, y] = coords;
---

## Valores por defecto

Es útil cuando una propiedad puede faltar:

    const { theme = "light" } = settings;
