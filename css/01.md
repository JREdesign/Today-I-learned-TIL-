# CSS – Notas iniciales

Este archivo recoge algunos conceptos y recordatorios básicos sobre CSS que voy aprendiendo o repasando, centrados principalmente en layout, comportamiento del modelo de caja y propiedades comunes en proyectos reales.

---

# Box model y su impacto en el layout

El modelo de caja de CSS define cómo se calculan el tamaño y el espacio que ocupa un elemento. Está compuesto por el contenido, el padding, el borde y el margen.

Por defecto, los navegadores utilizan el valor `content-box`, lo que significa que el ancho y alto definidos solo afectan al contenido, y el padding y el borde se suman al tamaño final del elemento.

Esto puede provocar cálculos inesperados en layouts complejos.

---

# Uso de box-sizing: border-box

Al usar `box-sizing: border-box`, el padding y el borde pasan a formar parte del ancho y alto definidos, haciendo que el comportamiento del layout sea más predecible.

Es habitual aplicar esta regla de forma global:

    *,
    *::before,
    *::after {
      box-sizing: border-box;
    }

Esto simplifica el cálculo de tamaños y evita muchos problemas al maquetar interfaces.

---

# Diferencia entre display: none y visibility: hidden

Ambas propiedades ocultan un elemento, pero su comportamiento es distinto:

- `display: none` elimina completamente el elemento del flujo del documento.
- `visibility: hidden` oculta el elemento, pero mantiene el espacio que ocupa.

Elegir una u otra depende de si se quiere conservar o no el espacio dentro del layout.

---

## Unidades relativas más comunes

Las unidades relativas permiten crear diseños más flexibles y adaptables:

- `em`: relativa al tamaño de fuente del elemento padre.
- `rem`: relativa al tamaño de fuente raíz del documento.
- `%`: relativa al tamaño del contenedor.
- `vh` y `vw`: relativas al tamaño de la ventana del navegador.

El uso correcto de estas unidades es clave para un diseño responsive.

# CSS – Inline vs Inline-block

Los valores `inline` e `inline-block` del atributo display se parecen, pero tienen diferencias importantes en cuanto a comportamiento y layout.

Un elemento con `display: inline`:

- No acepta ancho ni alto.
- Ocupa solo el espacio de su contenido.
- Se comporta como texto dentro de una línea.


Un elemento con `display: inline-block`:

- Acepta width y height.
- Permite aplicar márgenes verticales.
- Se coloca en línea con otros elementos.

Usar `inline-block` es útil cuando se necesita controlar el tamaño de un elemento sin romper el flujo en línea.

---

# Propiedad overflow en CSS

La propiedad overflow controla qué ocurre cuando el contenido de un elemento supera el tamaño de su contenedor.

Los valores más comunes son:

- visible: el contenido se muestra fuera del contenedor.
- hidden: el contenido sobrante se oculta.
- scroll: siempre muestra barras de desplazamiento.
- auto: muestra barras solo cuando es necesario.

El uso correcto de overflow es importante para evitar desbordamientos inesperados y mejorar la experiencia de usuario en layouts complejos.

---

# Especificidad en CSS y uso de !important

La especificidad determina qué regla CSS se aplica cuando varias reglas afectan al mismo elemento. A grandes rasgos, se puede pensar como una prioridad.

Orden típico (de menor a mayor):

- selectores de tipo (por ejemplo, div, p)
- clases, atributos y pseudo-clases (por ejemplo, .btn, [disabled], :hover)
- ids (por ejemplo, #header)
- estilos inline (atributo style)

El modificador `!important` fuerza una regla, pero usarlo de forma habitual suele causar CSS difícil de mantener. Es preferible mejorar la estructura de selectores o reorganizar estilos antes de recurrir a `!important`.

# CSS – Margin collapse

El margin collapse (colapso de márgenes) ocurre cuando márgenes verticales de elementos de bloque se combinan y el resultado no es la suma de ambos, sino el mayor de los dos. Esto puede sorprender cuando un contenedor parece no “respetar” el margen superior de su primer hijo.

---

# Caso típico

---

## Caso típico

Si el primer hijo tiene margin-top, ese margen puede colapsar con el margen del contenedor y parecer que el contenedor “no tiene padding” o que el margen se sale hacia fuera.

---

## Formas comunes de evitarlo

Una manera sencilla es añadir padding al contenedor:

    .container {
      padding-top: 1px;
    }

Otra opción es crear un nuevo contexto de formato, por ejemplo usando overflow:

    .container {
      overflow: auto;
    }

Entender esto ayuda a depurar muchos “misterios” de espaciado vertical en layouts.

# CSS – Flex gap y alternativas

La propiedad gap se puede usar no solo en CSS Grid, sino también en contenedores Flexbox, y es una forma limpia de separar elementos sin tener que aplicar márgenes individuales.

---

# gap en Flexbox

En un contenedor con display: flex, gap añade separación entre los ítems:

    .row {
      display: flex;
      gap: 12px;
    }

Esto evita trucos como aplicar margin-right a todos menos al último, y hace el layout más mantenible.

---

# Alternativa cuando gap no es posible

Si por algún motivo no puedes usar gap, una alternativa clásica es usar márgenes y un selector para evitar el último:

    .row > * {
      margin-right: 12px;
    }

    .row > *:last-child {
      margin-right: 0;
    }

Aun así, cuando se puede, gap suele ser más limpio y menos propenso a errores.

# CSS – Stacking context y z-index

A veces un z-index “no funciona” aunque parezca correcto. Muchas veces la causa real es el stacking context (contexto de apilamiento), que define cómo se ordenan los elementos en el eje Z.

---

## Idea clave

z-index solo tiene efecto en elementos posicionados (por ejemplo, position: relative/absolute/fixed/sticky) y dentro de un contexto de apilamiento.

Además, ciertos elementos crean un nuevo stacking context, por ejemplo con transform, opacity menor que 1, o position con z-index, entre otros.

---

## Consejo práctico

Cuando un overlay o dropdown queda detrás de algo:

- confirmar que el elemento tiene position (si aplica)
- revisar si algún padre crea stacking context (por ejemplo transform)
- probar a mover el overlay a un contenedor superior (portal) si es UI compleja

Entender stacking context evita horas de frustración con z-index.

# CSS – min-content, max-content y fit-content

CSS tiene palabras clave útiles para tamaños basados en el contenido, especialmente en layouts donde el ancho no debe ser fijo.

---

## min-content

El elemento se reduce al mínimo posible sin romper reglas (por ejemplo, rompiendo líneas).

---

## max-content

El elemento se expande para ocupar el ancho máximo que el contenido necesita sin saltos de línea.

---

## fit-content

Intenta ajustarse al contenido pero con límites; suele ser útil en componentes que no deben crecer sin control.

Estas propiedades son útiles en layouts avanzados, especialmente combinadas con grid y contenedores responsivos.

---

# CSS – Por qué rem es útil en tipografía

rem es una unidad relativa al tamaño de fuente raíz del documento (normalmente HTML). Usarla en tipografía ayuda a mantener escalado consistente y mejora accesibilidad cuando el usuario cambia el tamaño base del navegador.

Una práctica habitual es definir un tamaño base y luego usar rem para títulos, textos y espaciados relacionados con tipografía.
