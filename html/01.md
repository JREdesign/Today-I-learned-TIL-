## HTML – Notas iniciales

Este archivo recoge varios conceptos y recordatorios básicos sobre HTML que he ido aprendiendo o repasando, organizados en secciones independientes para facilitar su consulta futura.

---

## Diferencia entre &lt;section&gt; y &lt;article&gt;

El elemento &lt;section&gt; se utiliza para agrupar contenido relacionado dentro de una página, mientras que &lt;article&gt; representa una unidad de contenido independiente que podría existir por sí misma, como una entrada de blog, un comentario o una tarjeta de producto.

---

## Para qué sirve el meta viewport

El meta viewport indica al navegador cómo debe adaptar el contenido al ancho real del dispositivo, siendo fundamental para un diseño responsive correcto.

Ejemplo habitual:

    <meta name="viewport" content="width=device-width, initial-scale=1">

# Atributos globales en HTML

Existen ciertos atributos que pueden aplicarse a prácticamente cualquier elemento HTML. Algunos de los más comunes son id, class, title, lang, data-*, hidden y tabindex. Estos atributos permiten controlar aspectos de accesibilidad, estilo y comportamiento.

---

## Uso correcto de la etiqueta &lt;label&gt;

La etiqueta &lt;label&gt; se utiliza para describir controles de formulario y debe estar correctamente asociada a su input correspondiente para mejorar la accesibilidad y la experiencia de usuario.

Ejemplo con atributo for:

    <label for="email">Correo electrónico</label>
    <input type="email" id="email">

---

## Uso de la etiqueta &lt;link&gt;

La etiqueta &lt;link&gt; se utiliza para establecer relaciones entre el documento HTML y recursos externos como hojas de estilo, iconos o archivos de manifiesto, y suele colocarse dentro del elemento &lt;head&gt;.

Ejemplo básico:

    <link rel="stylesheet" href="styles.css">

# HTML – Atributos booleanos

En HTML existen ciertos atributos conocidos como atributos booleanos. Su sola presencia indica que están activados, independientemente del valor que se les asigne.

Algunos ejemplos comunes son disabled, checked, required, readonly o autofocus.

Cuando un atributo booleano está presente, se considera verdadero:

    <input type="checkbox" checked>

También es válido escribirlo sin valor explícito:

    <input type="checkbox" checked>

Si el atributo no está presente, se considera falso.

Comprender este comportamiento evita errores al manipular formularios y al generar HTML dinámicamente desde JavaScript.

---

## Atributos data-* en HTML

Los atributos `data-*` permiten almacenar información personalizada en elementos HTML sin afectar la semántica. Son muy útiles cuando necesitas asociar datos a un elemento para leerlos desde JavaScript o para debugging.

Ejemplo:

    <button data-id="42" data-action="delete">Eliminar</button>

En JavaScript se pueden leer mediante dataset. Por ejemplo, data-id se convierte en dataset.id.

Usar `data-*` suele ser una solución limpia cuando necesitas “marcar” elementos sin introducir clases o ids solo para lógica.

# HTML – Formularios y atributos booleanos

En HTML existen atributos booleanos cuyo valor real no depende de lo que escribas, sino de si el atributo está presente o no. Esto aparece mucho en formularios y puede confundir al principio.

---

##Atributos booleanos

Algunos atributos booleanos comunes son disabled, checked, required, readonly, multiple o autofocus.

Si el atributo está presente, se considera activado:

    <input type="checkbox" checked>

Si no está presente, se considera desactivado.

En HTML, escribir checked="false" no “desactiva” el atributo; si aparece, cuenta como verdadero.

---

## required y validación del navegador

El atributo required hace que el navegador bloquee el envío del formulario si el campo está vacío (según el tipo de input).

Ejemplo:

    <input type="email" required>

Esto no sustituye la validación del lado servidor, pero ayuda a mejorar experiencia de usuario y reduce errores básicos.

# HTML – Accesibilidad rápida: nombres accesibles

En accesibilidad, un punto clave es que los controles interactivos tengan un nombre accesible para lectores de pantalla. A veces el texto visible ya lo proporciona, pero en icon buttons o inputs sin label se puede perder.

---

##aria-label en botones con icono

Si un botón solo tiene un icono, conviene añadir un nombre accesible:

    <button aria-label="Cerrar">X</button>

---

## Preferir &lt;label&gt; cuando es un formulario

Para inputs, lo ideal es usar &lt;label&gt; asociado con for e id, y dejar aria-label como solución puntual cuando no puedas mostrar un label visible.

Esto mejora la experiencia para usuarios que navegan con teclado o lector de pantalla.

---

# HTML – type en &lt;button&gt; dentro de formularios

Un detalle importante: dentro de un formulario, un &lt;button&gt; sin atributo type suele comportarse como botón de envío. Esto puede provocar envíos accidentales al hacer clic en un botón que solo pretendía cancelar o abrir un modal.

---

## Comportamiento por defecto

Dentro de un &lt;form&gt;, un botón sin type puede actuar como submit.

Ejemplo:

    <form>
      <button>Guardar</button>
    </form>

---

## Recomendación práctica

Es buena práctica ser explícito:

    <button type="submit">Guardar</button>
    <button type="button">Cancelar</button>

Esto evita bugs tontos y hace el HTML más claro.

# HTML – loading="lazy" en imágenes

El atributo loading en &lt;img&gt; permite controlar cómo se cargan las imágenes, y puede mejorar rendimiento en páginas largas.

---

## loading="lazy"

Indica al navegador que difiera la carga de la imagen hasta que esté cerca del viewport:

    <img src="foto.jpg" loading="lazy" alt="..." />

---

## Cuándo usarlo

- Galerías
- Listados largos
- Páginas con muchas imágenes “below the fold”

---

# HTML – Atributo alt en &lt;img&gt;
El atributo alt proporciona un texto alternativo para imágenes. Es clave para accesibilidad y para casos donde la imagen no se carga.
No sustituye técnicas avanzadas, pero es una mejora simple y efectiva.

---

## Cuándo describir
Si la imagen aporta información (por ejemplo, un gráfico o una foto relevante), alt debería describir el contenido de forma útil.

---

## Cuándo dejarlo vacío

Si la imagen es puramente decorativa, es válido usar alt vacío para que lectores de pantalla la ignoren:

    <img src="decoracion.svg" alt="" />

No es recomendable omitir alt: si lo omites, algunos lectores pueden anunciar la ruta del archivo.
